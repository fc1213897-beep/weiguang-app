1. 你要解决什么问题

1.1 业务目标

用户在电脑浏览器打开微光，希望用微信登录。实现方式是：电脑展示微信小程序码 → 手机扫码在小程序里确认 → 电脑自动登录。

技术方案一句话：电脑生成一次性暗号 scene 并画进小程序码 → 小程序把 scene 和微信 code 交给本机 Next.js → 后端换 openid 写入 Supabase → 电脑轮询发现完成 → 兑换浏览器登录 Session。

3. 核心概念词典

3.1 scene（场景值）

项目说明
是什么每次点「微信扫码登录」时随机生成的一串字符
不是什么不是磁盘文件，不是固定配置
作用绑定「电脑这次等待」和「手机这次扫码」
怎么传编进小程序码 → onLoad(options.scene)
存在哪Supabase 表 wx_login_sessions

类比：餐厅叫号——电脑拿号等，手机扫码等于叫到号。

3.2 AppID / AppSecret / code / openid

概念说明
AppID标识小程序，可在 .env 配置
AppSecret仅 Next.js 服务端使用，禁止写入小程序
codewx.login() 临时凭证，给后端换 openid
openid用户在你小程序里的唯一 ID

3.3 数据库状态 status

值含义
pending已出码，等人扫码
completed已写入 openid（必须用这个词，不是 confirmed）
consumed网页已兑换登录
expired超时

4. 完整成功流程

步谁做什么
1用户设置页点「微信扫码登录」
2Next.js生成 scene，插入 DB，向微信要小程序码
3用户手机微信扫小程序码（非普通编译）
4小程序onLoad 收到 scene，点「允许登录」
5Next.jswx-callback：code→openid，status=completed
6浏览器轮询 Supabase → exchange → setSession 登录成功

5. 本地联调原理

5.1 为什么 localhost 能用？

备案主要影响正式「网页 OAuth 回调域」。本方案是：本机 Next 直连微信 API；小程序在开发期可请求 localhost（勾选不校验合法域名）。

5.2 两条线

线路路径
出码浏览器 → 本机 Next → 微信 API
确认小程序 → localhost:3000/api/auth/wx-callback

5.3 普通编译 vs 扫电脑码

方式有 scene能登录
开发者工具「普通编译」否需手动填 scene 调试
扫电脑网页生成的小程序码是是

8. 操作 Checklist

  • .env.local 配齐，WX_MP_ENV_VERSION=develop
  • Supabase 已建 wx_login_sessions 表
  • 开发者工具导入 miniprogram，AppID 一致
  • 勾选不校验合法域名
  • 编译后模拟器可见登录页
  • npm run dev 运行中
  • /api/auth/wx/ping 返回 ok
  • 设置页出码，手机微信扫码
  • 小程序点「允许登录」
  • 电脑显示已登录

9. 上线注意事项

  • 小程序 request 合法域名改为正式 HTTPS 域名
  • config.js 不能用 localhost
  • Secret、Service Role 勿提交 Git
  • 正式环境扫码可用 release 版小程序码

10. 附录：API 与数据库

方法路径调用方

结语：scene 是「一次登录的配对号」；本机 Next.js 是桥梁；Supabase 是状态板。你已跑通闭环，以后按 Checklist 逐项核对即可。
