# 微光 · 服务器部署指南

本文说明：**代码已 `git pull` 到最新之后**，在服务器和小程序端分别要做什么。

---

## 一、先搞清楚：改了什么？

| 改动位置 | 典型内容 | 服务器要做什么 | 小程序要做什么 |
|----------|----------|----------------|----------------|
| `app/`、`lib/` | API、登录、任务、聊天后端 | **必须** build + 重启 | 一般不用 |
| `miniprogram/` | 页面、样式、TabBar、config | 仅 API 地址变时才动服务器 | **必须** 开发者工具编译/上传 |
| `.env` / 环境变量 | 微信 Secret、Supabase、AI | 改完 env 后 **重启** | 不用 |
| 两边都改 | 全栈功能 | 都要 | 都要 |

> **重要：** 只 `git pull` **不会**让正在运行的服务自动更新，必须执行下面的构建和重启。

---

## 二、服务器标准流程（每次 pull 之后）

SSH 登录服务器后执行：

```bash
cd ~/weiguang-app

# 1. 确认已是最新（可选，建议做一次）
git fetch origin
git status
git log -1 --oneline

# 2. 依赖有变化时再装（package.json 没变可跳过）
npm install

# 3. 编译 Next.js
npm run build

# 4. 重启进程
pm2 restart weiguang-app

# 5. 看日志是否有报错
pm2 logs weiguang-app --lines 30
```

查看进程状态：

```bash
pm2 status
```

## 三、环境变量（`.env`）

- 服务器上的 `.env` / `.env.local` **不要提交到 Git**，需在服务器单独维护。
- 新增或修改环境变量后，只需：

```bash
pm2 restart weiguang-app
```

- 小程序请求的地址应与服务器一致：
  - 服务器：`NEXT_PUBLIC_APP_URL`（见 `.env.local`）
  - 小程序：`miniprogram/utils/config.js` 中 `API_BASE_PROD`（体验版/正式版/提审）

| 环境 | 地址示例 |
|------|----------|
| 开发（开发者工具） | `http://www.weiguanglife.top:3000` |
| 体验版 / 正式版 / 提审 | `https://www.weiguanglife.top`（HTTPS，无端口） |

### HTTPS 与合法域名（提审必做）

出现 `request:fail url not in domain list` 时，通常是以下任一项未满足：

1. **服务器 443 已通**：云主机安全组放行 443；Nginx 反代到本机 `3000`（示例见 `deploy/nginx-weiguang.example.conf`）
2. **证书有效**：例如 `certbot certonly --nginx -d www.weiguanglife.top`
3. **环境变量**：服务器 `.env` 中 `NEXT_PUBLIC_APP_URL=https://www.weiguanglife.top`
4. **微信后台**：[微信公众平台](https://mp.weixin.qq.com) → 开发 → 开发管理 → 开发设置 → **服务器域名** → request 合法域名填写：`www.weiguanglife.top`（不要带 `https://` 和端口）
5. **重新上传**小程序代码后，用真机预览/体验版验证（开发者工具勾选「不校验合法域名」仅对开发版有效）

验证 HTTPS：

```bash
curl -I https://www.weiguanglife.top/api/auth/wx/ping
```

应返回 `HTTP/2 200` 或 `HTTP/1.1 200`。

## 四、验证接口是否部署成功

把域名换成你的：

```bash
curl -X POST http://www.weiguanglife.top:3000/api/auth/wx/mp-login
```

| 返回 | 含义 |
|------|------|
| **400**，提示类似「缺少 code」 | 接口**存在**，部署正常 |
| **404** | 接口未生效：检查是否 `build`、是否 `pm2 restart`、pull 的分支是否正确 |
| 连接失败 | 服务未启动、防火墙、端口未开放 |

其他常用接口（小程序会用到）：

- `POST /api/auth/wx/mp-login` — 小程序登录
- `GET/POST /api/mp/tasks` — 今日任务
- `GET/POST /api/mp/chat/...` — 小光聊天

更完整的「手动上传文件清单」见：[服务器上传清单.md](./服务器上传清单.md)（GitHub 拉不动时的备用方案）。

## 五、确认 pull 的真的是「最新」

在服务器执行：

```bash
cd ~/weiguang-app
git fetch origin
git rev-parse HEAD
git rev-parse origin/main    # 分支名按实际改：main / master
```

两条 commit 哈希**一致** → 本地与远端该分支同步。

若 `git status` 显示 `behind`，再执行：

```bash
git pull
```

## 六、小程序端发布流程

1. 用微信开发者工具打开本仓库下的 `miniprogram` 目录（或整个项目，按你习惯）。
2. 检查 `miniprogram/utils/config.js` 中 `API_BASE` 与服务器一致。
3. **编译** → 真机预览自测。
4. 确认登录、任务、聊天正常后 → **上传** 体验版 / 提交审核。

详细扫码登录说明见：`miniprogram/新手必读-扫码登录.md`。

## 七、Git pull 失败时的网络配置（可选）

若在服务器上 `git pull` 经常断线，可临时加大缓冲区并强制 HTTP/1.1：

```bash
git config --global http.postBuffer 524288000
git config --global http.version HTTP/1.1
```

说明：

- 这两行只解决 **传输稳定性**，不改变拉取的是哪份代码。
- `pull` **成功且无冲突** 时，就是当时远端该分支上的最新提交。
- 更稳妥的长期方案：改用 **SSH** 地址拉取仓库。

### pull 直接超时（Failed to connect to github.com port 443）

说明服务器 **连不上 GitHub**（防火墙 / 跨境网络），`postBuffer` 和 HTTP/1.1 **解决不了**。

**推荐：本机 WinSCP 上传**（见 [服务器上传清单.md](./服务器上传清单.md)），然后 `npm run build` + `pm2 restart`。

可先测网络：

```bash
curl -I --connect-timeout 10 https://github.com
```

若超时，可尝试（任选其一，不保证每台机器都通）：

```bash
# 方案 A：加长超时
git config --global http.lowSpeedLimit 0
git config --global http.lowSpeedTime 600

# 方案 B：GitHub 加速前缀（镜像失效时需换别的）
git config --global url."https://ghfast.top/https://github.com/".insteadOf "https://github.com/"
git pull
# 不用后恢复：git config --global --unset url.https://ghfast.top/https://github.com/.insteadof

# 方案 C：仓库同步到 Gitee，服务器改 remote 从 Gitee pull
```

## 八、常见问题

### 1. 小程序登录失败 404

服务器还没有新接口 → 按本文 **第二节** 执行 `npm run build` 和 `pm2 restart weiguang-app`。

### 2. pull 成功但功能没变

忘记 `build` 或 `restart`；或改的是小程序却只在服务器 pull 了。

### 3. 服务器改了代码、没 push

本地开发机与服务器不一致；应以 Git 远端为准，避免只在服务器手改。

### 4. build 报错

看终端完整报错；常见原因：Node 版本不对、缺环境变量、依赖未 `npm install`。
